## 4. 部署步驟（使用者同意後才執行）
1. **備份**：複製 `/opt/demo/Caddyfile` 為 `Caddyfile.bak-日期`；匯出揮發度系統資料庫（pg_dump）到 `/opt/backup/`。
2. **加 2 GB swap**（記憶體不夠時的緩衝，不另收費）。
3. **上傳**安裝包到 `/opt/travel`，建立正式 `.env`：全新隨機密碼、`DAILY_CHAT_LIMIT=50`、`DAILY_COST_LIMIT_USD=0.30`、`PUBLIC_URL`、`EDGE_NETWORK=voldemo_default`；Claude 金鑰由使用者決定要不要放。
4. **啟動**：`docker compose -p travel -f docker-compose.yml -f docker-compose.prod.yml up -d --build`。
5. **接上網址**：在 Caddyfile 加一段 `travel.34-80-26-168.sslip.io { encode gzip; reverse_proxy travel-app-1:8000 }`，先 `caddy validate` 檢查格式，再 `caddy reload`（不中斷揮發度系統）。
6. **上線後檢查**：兩個網址都打得開、HTTPS 憑證正常；主機上跑全部測試；本機用公開網址跑畫面測試；看記憶體。

## 5. 恢復方案（出問題時）
| 狀況 | 怎麼恢復 | 約需時間 |
|---|---|---|
| 旅遊系統有問題，揮發度正常 | `docker compose -p travel down`；Caddyfile 拿掉旅遊那段、`caddy reload` | 1 分鐘 |
| 揮發度系統受影響 | 還原 `Caddyfile.bak-日期`、`caddy reload`；必要時用備份還原資料庫 | 5 分鐘 |
| 主機記憶體不夠、整台變慢 | 先停旅遊系統（同第一列）；再和使用者討論升級主機（每月約多 25 美元） | 1 分鐘 |
| 要完全撤掉 | `docker compose -p travel down -v`、刪 `/opt/travel`、還原 Caddyfile | 3 分鐘 |
