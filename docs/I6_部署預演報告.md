- 日期：2026-11-04
- 紀錄：`docs/過程截圖/I6_部署預演/預演輸出.txt`、`記憶體紀錄.csv`、畫面截圖
- 腳本：`tools/prod_rehearsal.sh`、`tools/load_test.py`、`tools/api_matrix_test.py`、`tools/api_coverage.py`

## 1. 預演條件（和正式主機相同）
| 項目 | 設定 |
|---|---|
| 設定檔 | `docker-compose.yml`＋`docker-compose.prod.yml`（正式版） |
| 對外埠號 | 旅遊系統 0 個；只有模擬的 Caddy 對外，所有請求經過 Caddy |
| 記憶體上限 | 每個服務各自限制，加總約 2.8 GB（正式主機可用約 2.8 GB） |
| 同時運作 | 揮發度系統（本機副本）一起跑，模擬兩個系統共用一台主機 |
| AI 上限 | 每日 50 次、0.30 美元（預演沒有放金鑰，不花費） |
| 密碼 | 全部隨機產生，預演結束刪除 |

## 2. 結果
| 檢查 | 結果 |
|---|---|
| API 覆蓋 | 64/64 支都有測試（`docs/API覆蓋表.md`） |
| 全部後端測試（14 支） | 全部通過：API 68、帳號 27、合作夥伴 21、AI 流程 29、多 Agent 24、採購 32、自動化 11、評測機制 15、RAG 16/16、監控 21、開放資料 23、爬蟲 19、**全面掃描 22**、MCP 15 |
| 經過 Caddy 的畫面測試 | 通過（和客人走同一條路） |
| 對外埠號 | 旅遊系統沒有任何對外埠號 |
| **壓力測試** | 20 人同時 60 秒，共 9,486 次請求（每秒約 158 次），**錯誤 0**；P95：首頁 0.16 秒、查行程 0.14、試算 0.17、查景點 0.27、搜尋規定 0.20 |
| **記憶體尖峰** | 旅遊系統合計 **1,561 MB**（主機可用約 2,800 MB）；最大是 app 791 MB、n8n 434 MB |
| 記憶體不足被砍掉 | 11 個容器全部 OOMKilled＝false、重啟 0 次 |

調整：app 的上限從 900 MB 提高到 1,024 MB（尖峰 791 MB 太接近 900）。

## 3. 結論
在 4 GB 主機上和揮發度系統一起跑，記憶體還有約 1.2 GB 餘裕；20 人同時使用沒有錯誤、回應都在 0.4 秒內。**技術上可以上線**，等使用者人工驗收並決定。

## 4. 注意
- 本機 CPU 比主機（e2-medium，2 個共享核心）快，正式環境的回應時間會比預演慢；上線後會再量一次。
- AI 客服沒有在預演中測速度（沒放金鑰）；AI 回應時間主要取決於 Claude API，約 3～10 秒。
