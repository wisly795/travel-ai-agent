# D 階段 採購 Agent：測試報告

- 日期：2026-11-03
- 截圖：`docs/過程截圖/D_採購Agent/`
- 模型：claude-opus-5-5（較強模型），effort medium，開啟 server-side fallback（拒答時由伺服器自動改用合適模型）

## 流程
報價成交 → 自動產生請購單（預算＝報價裡的住宿費）→ 業務按「AI 比價」→ AI 讀請購單與三家供應商報價，建立採購單草稿並寫理由 → 人核准（大額或超出預算要主管）或退回（必填原因）→ 核准後呼叫模擬供應商 API 下單，取得確認編號；失敗可重送。

## 自動測試（不花 API 額度，`tools/procurement_test.py`）：28/28
- 成交自動產生請購單、預算正確（NT$ 19,200）
- 三家供應商總價與價差由系統計算
- AI 建立草稿、使用較強模型與 fallback、比價過程記在 AI 對話紀錄
- 待核准時不能重複比價；退回必填原因；退回後回到待比價
- AI 看得到退回原因、看不到舊分析
- 業務核准下單取得確認編號；已下單不能再核准
- 大額（NT$ 132,600、57,120）標記需主管；業務核准 403；主管核准成功
- 房量不足的供應商被系統擋下，AI 改選有房量的
- 供應商故障下單失敗 → 故障中重送仍失敗 → 恢復後重送成功
- 報價取消時待核准草稿自動退回、請購單取消
- 未登入 401；主管權杖也能看後台

| 8 人京都，NT$ 124,800 | 標記需要主管；業務按核准，畫面提示「請先輸入主管權杖」；輸入主管權杖後下單成功 |

## 實測發現並修正
1. **大額核准的錯誤訊息不清楚**：沒填主管權杖時顯示「業務權杖不正確」。改成先提示「需要主管核准，請先輸入主管權杖」。
2. **AI 自己算價差**：AI 在理由中寫了自己算的價差，並主動承認違反規則。改成由系統提供 `diff_vs_cheapest`，規則要求用這個欄位。
3. **AI 看到舊分析而混淆、拿不到退回原因**：給 AI 的請購單改為不含舊分析，並附上 `previous_rejections`（被退回的供應商、金額、原因），規則要求回應退回原因。

## 已知限制
- 請購單沒有出發日期（AI 也指出這點），所以無法判斷「現在是否還在免費取消期限內」。之後可在報價加上出發日期。
- 模擬供應商的確認編號存在記憶體，ERP 容器重啟後編號會從頭開始（展示用可接受）。
- 每次 AI 比價約花 0.05–0.15 美元，比客服貴，所以只在業務按鈕時才執行。
