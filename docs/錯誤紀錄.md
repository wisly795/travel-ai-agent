# 開發錯誤紀錄

記錄開發時遇到的錯誤、原因和處理方式，作為作品集與交接資料。截圖放在 `docs/過程截圖/錯誤/`；終端機錯誤以原始訊息文字保存。

## 階段 A：AI 客服（2026-11-03）

### A-1 畫面測試的瀏覽器沒有裝成功
- **現象**：執行畫面自動測試時，Playwright 顯示：
  ```text
  Looks like Playwright was just installed or updated.
  Please run the following command to download new browsers:
      playwright install
  ```
- **原因**：`playwright install --with-deps chromium` 在測試用容器裡下載瀏覽器失敗，但錯誤訊息被隱藏，直到執行測試才發現沒有瀏覽器。
- **處理**：改用系統套件安裝 Chromium（`apt-get install chromium`），並用 `CHROME=/usr/bin/chromium` 指定瀏覽器位置。重跑後全部通過。
- **學到的事**：安裝步驟不要把錯誤訊息全部隱藏，否則失敗時會在後面的步驟才出錯，較難追查。

### A-2 `.env` 中文註解在 PowerShell 顯示成亂碼
- **現象**：在 PowerShell 讀取 `.env` 時，中文註解顯示成亂碼。
- **原因**：PowerShell 5.1 預設用系統編碼（Big5）讀檔，但檔案是 UTF-8。
- **處理**：改用其他工具檢查，確認檔案內容正確、沒有多餘的 BOM 字元。只是顯示問題，不影響系統。
- **學到的事**：看到亂碼先分清楚是「檔案壞了」還是「讀檔方式不對」。

### A-3 覆寫檔案前沒有先讀取
- **現象**：Claude 的寫檔工具拒絕覆寫 `main.py`、`requirements.txt`，訊息是 `File has not been read yet`。
- **原因**：專案剛複製到新資料夾，工具規定要先讀過新位置的檔案才能覆寫，避免蓋掉沒看過的內容。
- **處理**：先讀取新資料夾的檔案，再覆寫。屬於開發工具的保護機制，不是系統錯誤。

### A-4 AI 從姓名推測性別（使用者實測發現）
- **現象**：使用者輸入「你好 我是杜正威」，AI 回「杜先生您好」。截圖：`docs/過程截圖/A_AI客服/10_使用者實測_發現稱謂問題.webp`。
- **原因**：規則沒有規定怎麼稱呼客人，模型就依姓名猜性別。姓名不代表性別，猜錯會冒犯客人。
- **處理**：在 AI 規則加上「稱呼客人用『您』或全名加『您好』，不從姓名推測性別，不用先生、小姐、女士」。
- **驗證**：新增回歸測試 `tools/live_name_test.py`，用 4 個姓名實測，4/4 都改成「全名＋您好」；原本的模擬流程 20/20、API 27/27 仍通過（有金鑰時不跑「沒有金鑰回 503」那一項）。
- **學到的事**：自動測試只測得到事先想到的情況；真人實際使用才會發現這類問題。發現後要補一個測試，避免以後改規則時又壞掉。

## 階段 B：RAG 規定問答（2026-11-03）

### B-1 口語問法找不到正確條文
- **現象**：檢索評測中，「人數不夠會不會開團」找不到「取消與退費規定 第5條」，正確條文排在第 6 名，相似度只有 0.27。
- **原因**：條文寫「報名人數未達 10 人」，客人說「人數不夠、開團」，用字差太多；小型多語向量模型對口語理解有限。換成「旅行社會不會因為人太少取消行程」時，相似度可達 0.81。
- **處理**：
  1. 補強文件：條文標題加上業界常用說法「人數不足未成團」，分數升到 0.30，仍不足以排進前 3 名。
  2. 讓 AI 改寫查詢：工具說明加上「第一次找不到時，換成文件可能使用的說法再查一次」。真實 Claude 測試時，AI 成功找到第 5 條並正確回答。
  3. 評測把這題標成「已知弱點」，保留紀錄，不刪題目。
- **之後可以怎麼改善**：換成較大的向量模型（例如 multilingual-e5-large，但約 2GB，雲端主機記憶體吃緊），或加上關鍵字搜尋做混合檢索。
- **學到的事**：RAG 的好壞不只看模型，文件寫法和查詢方式一樣重要；要用評測題組量化，而不是只試幾題覺得可以。

### B-2 換資料庫映像檔要清空資料
- **現象**：pgvector 需要換成 `pgvector/pgvector:pg15` 映像檔。
- **原因**：原本的 `postgres:15-alpine` 沒有向量擴充；兩者底層系統不同（alpine 與 debian），沿用舊資料可能有排序規則不一致的問題。
- **處理**：因為都是測試資料，用 `docker compose down -v` 清空後重建。行程、飯店由 `db/02_seed.sql` 自動建回。正式環境不能這樣做，要先備份再搬移資料。

### B-3 重建容器後測試腳本不見
- **現象**：重建後執行 `python rag_eval.py` 出現 `No such file or directory`。
- **原因**：測試腳本是用 `docker cp` 複製進容器的，容器重建後會回到映像檔的原始狀態。
- **處理**：每次測試前重新複製全部測試腳本。

## 階段 C：業務後台與 ERP（2026-11-03）

### C-1 截圖存錯資料夾
- **現象**：C 階段截圖資料夾裡混入了 6 張「全系統回歸測試」的截圖。
- **原因**：回歸測試腳本預設把截圖存到掛載的 `/shots`，而這次掛載的是 C 階段資料夾。
- **處理**：刪除混入的 6 張（B 階段資料夾已有同內容），之後回歸測試改存暫存資料夾。

### C-2 CSV 空欄位顯示成 None
- **現象**（寫程式時發現，未上線）：沒有 ERP 同步的報價，匯出 CSV 時欄位會出現文字 `None`。
- **處理**：`safe_cell` 把空值轉成空字串。

## 階段 D：採購 Agent（2026-11-03）

### D-1 測試預期寫錯：14 人採購要主管核准
- **現象**：採購測試在「供應商故障」那一步出現 `KeyError: 'status'`，伺服器紀錄是 `403 Forbidden`。
- **原因**：14 人要 7 間房，採購金額 NT$ 57,120，超過主管門檻 NT$ 30,000，系統正確擋下業務；是測試用錯權杖。
- **處理**：測試改用主管權杖，並新增一項檢查「14 人採購金額超過門檻要主管」。
- **學到的事**：測試失敗時先看伺服器紀錄的狀態碼，再判斷是系統錯還是測試錯。

### D-2 安裝瀏覽器測試套件逾時
- **現象**：`pip install playwright` 出現 `ReadTimeoutError`。
- **原因**：每次測試都在新容器裡重新下載瀏覽器和套件，網路不穩就失敗。
- **處理**：做一個專用測試映像檔 `travelquote-uitest`（`tools/uitest/Dockerfile`），裝好 Chromium、中文字型、Playwright，之後直接使用。

### D-3 真實 AI 實測發現的三個問題
- 大額核准錯誤訊息不清楚、AI 自己算價差、AI 看到舊分析而混淆且拿不到退回原因。處理方式見 `docs/D_測試報告.md`「實測發現並修正」。
- **學到的事**：AI 系統要用真實模型實際跑過才看得到這類問題；給 AI 的資料要剛好夠用，多了會混淆，少了（例如退回原因）會做錯決定。

## 階段 E：n8n 自動化（2026-11-03）

### E-1 指令執行流程時找不到起點
- **現象**：`n8n execute --id=...` 回 `Missing node to start execution`。
- **原因**：指令執行需要「手動觸發」或「被其他流程呼叫」的節點，排程節點不算。
- **處理**：產生流程的程式自動替排程流程加上「手動執行」節點，接到同樣的下一步。

### E-2 n8n 任務代理埠號被占用
- **現象**：`n8n Task Broker's port 5679 is already in use`。
- **原因**：容器裡已經有一個 n8n 在跑，用指令再開一個會搶同一個埠。
- **處理**：執行指令時加上 `N8N_RUNNERS_BROKER_PORT=5680` 改用別的埠。

### E-3 每日報表程式碼語法錯誤
- **現象**：`SyntaxError: Invalid or unexpected token`。
- **原因**：Python 產生 JSON 時，程式碼裡的 `'\n'` 變成真的換行，JavaScript 字串被切斷。
- **處理**：改用 `String.fromCharCode(10)` 表示換行。
- **學到的事**：用程式產生另一種程式碼時，跳脫字元要特別小心；產生後要實際執行過。

### E-4 模擬測試的假用量算進每日上限
- **現象**：採購測試被「今天的 AI 使用量已達上限」擋下。
- **原因**：不花錢的模擬測試也會寫入 AI 用量紀錄，假的 token 數換算成「假花費」累積到 0.83 美元，加上真實花費超過 1 美元上限；真實客人也會被擋。
- **處理**：刪除 44 筆假紀錄（真實用量 18 次、0.18 美元保留）；模擬測試改成測試期間放寬上限、結束時刪除自己產生的紀錄。
- **學到的事**：測試不能污染正式的統計資料；同時也證明了每日上限真的會生效。

## 階段 F：MCP（2026-11-03）

### F-1 MCP 套件 2.x 改版
- **現象**：`No module named 'mcp.server.fastmcp'`。
- **原因**：MCP Python SDK 2.x 把 FastMCP 改名為 MCPServer，其他 API 也有變動。
- **處理**：固定使用 1.x 最新版 `mcp==1.30.0`（文件與範例最多、行為穩定），並在 Dockerfile 鎖定版本。
- **學到的事**：套件要鎖版本；看到大版本號變了，先讀遷移說明再決定升級還是固定。

### F-2 外部 AI 自己算退費
- **現象**：Claude 透過 MCP 回答退費時，自己算出扣款金額。
- **原因**：MCP 只提供查規定，沒有提供計算工具；AI 拿不到工具就會自己算。
- **處理**：新增退費計算 API 與 MCP 工具，重跑後 Claude 改用工具。
- **學到的事**：開放給外部 AI 的工具，要把「需要精確」的計算都做成工具，不能只靠提示。

## 階段 G：交付與安裝包（2026-11-03 晚上）

### G-1 安裝包放在中文資料夾會啟動失敗（安裝實測發現）
- **現象**：解壓到「旅遊AI客服系統」資料夾後執行 Start.bat，建置失敗：
  `header key "x-docker-expose-session-sharedkey" contains value with non-printable ASCII characters`
- **原因**：Docker 新版建置引擎（BuildKit）把資料夾路徑放進內部連線的標頭，標頭只能是英文字元；路徑有中文就失敗。使用者很可能解壓到中文資料夾（例如桌面的「新資料夾」）。
- **嘗試**：關掉 Compose 的 bake 模式（`COMPOSE_BAKE=false`）無效（ERP 那次成功只是剛好有快取）。
- **處理**：Start.bat 先用一般方式建置；失敗時自動改用相容模式（`DOCKER_BUILDKIT=0`）逐一建置三個映像檔，再啟動。重新實測：中文路徑安裝成功，約 10 分鐘，全部測試通過。輸出紀錄：`docs/過程截圖/G_交付/安裝過程_Start.bat輸出.txt`。
- **學到的事**：安裝包一定要在「全新資料夾、像使用者那樣」實際裝一次；開發環境的英文路徑測不出這種問題。

### G-2 指令列執行 Start.bat 被當成內建指令
- **現象**：用 `cmd /c Start.bat` 測試時出現「'Start.bat' is not recognized」。
- **原因**：cmd 有內建指令 `start`，直接打 `Start.bat` 可能被誤判。使用者雙擊執行不受影響。
- **處理**：測試時改用 `cmd /c .\Start.bat`。

### G-3 等待就緒的指令跳脫字元錯誤（重寫時順便修正）
- 舊版 Start.bat 在雙引號內寫了 `^|`，PowerShell 會收到多餘的 `^`。重寫時改成雙引號內直接用 `|`。

## 第二期 H2：帳號登入（2026-11-03 晚上）

### H2-1 同一個分頁換帳號，自動恢復上一位的登入
- **現象**：瀏覽器測試從業務換成主管時卡住，找不到登入欄位。
- **原因**：登入狀態存在分頁的 sessionStorage，重新打開網址會自動恢復業務的登入並隱藏登入表單。這是「重新整理保持登入」的正常行為，是測試腳本沒考慮到。
- **處理**：每個角色開全新的瀏覽器視窗（獨立的 context），並把「重新整理後保持登入」也加成一項檢查。
- **另外**：上一輪雖然在等待畫面時判斷失敗，但核准其實已經成功；用資料庫確認後，重新建立一張待主管核准的草稿再測。

### H2-2 後台時間顯示成世界標準時間
- **現象**：截圖上的登入時間顯示 14:48，實際台灣時間是 22:48。
- **原因**：前端用瀏覽器的時區顯示時間；測試用的瀏覽器在容器裡是世界標準時間。真實使用者在台灣不會遇到，但換到國外或伺服器端截圖就會錯。
- **處理**：時間顯示固定指定 `Asia/Taipei`。
- **學到的事**：時間要「存標準時間、顯示時指定時區」，不要依賴執行環境的預設值（和 H1 的「今天」同一類問題）。

## 第二期 H3／H4（2026-11-03 晚上）

### H3-1 圖表刻度出現 2.5 張
- 整數資料（張數）的中間刻度算成 2.5。處理：整數資料時最大值取偶數，中間刻度就是整數。

### H3-2 登入後預設畫面改變，舊測試找不到按鈕
- 後台預設改顯示儀表板後，畫面回歸測試找不到「下載 CSV」（在報價分頁裡）。處理：測試先切到報價分頁，並加一項「登入後預設顯示儀表板」的檢查。
- **學到的事**：改了預設畫面，要同步更新依賴那個畫面的測試。

### H4-1 網址中文沒有編碼
- **現象**：合作夥伴測試 `UnicodeEncodeError: 'ascii' codec can't encode characters`。
- **原因**：網址參數 `destination=沖繩` 直接放中文，Python 的 urllib 只接受編碼後的網址。
- **處理**：用 `urllib.parse.quote("沖繩")` 編碼。瀏覽器會自動編碼，所以畫面不受影響；寫程式呼叫 API 時要自己處理。

## 第二期 H5／H6（2026-11-03 晚上）

### H5-1 Mailpit 回傳純文字
- 清空信箱的 API 回傳「ok」而不是 JSON，測試腳本解析失敗。處理：解析失敗時當純文字。
- **學到的事**：串接外部服務前，先確認每支 API 實際回傳的格式，不要假設都是 JSON。

### H6-1 表情符號顯示成方框
- 評測結果用「✅」，在沒有表情字型的環境（測試用瀏覽器）顯示成方框。處理：改成文字加顏色。
- **學到的事**：重要資訊不要只靠表情符號或顏色，換台電腦可能就看不到。

### H6-2 截圖腳本的修改沒有生效
- 用指令（heredoc）建立的檔案，編輯工具要求先讀取才能修改；第一次修改失敗，補截的還是舊圖。處理：讀取後再修改，並在截圖前加檢查（至少 20 個「通過」）確認畫面是新的。

## 第三期 I1 Git＋CI（2026-11-04）

### I1-1 這台電腦沒有 Python，CI 腳本產生不了隨機密碼
- **現象**：CI 腳本在本機跑，`docker compose` 報「AUTOMATION_TOKEN is missing a value」。
- **原因**：腳本用 `python3` 產生隨機密碼，但 Windows 上的 `python3` 只是微軟商店的捷徑，沒有真的安裝，產生出空字串。
- **處理**：改用 `openssl rand -hex 16`（Git Bash 和 GitHub 的 Ubuntu 主機都有）。
- **學到的事**：CI 腳本要在「乾淨的環境」也能跑，不要假設對方電腦裝了什麼。

### I1-2 剛啟動就測，n8n 還沒準備好
- **現象**：全新啟動後跑自動化測試，「新報價自動產生通知」失敗；開發版一直開著時從沒出現過。
- **原因**：n8n 啟動時要先匯入、啟用 4 個流程，健康檢查通過時它還沒能接收 Webhook。
- **處理**：CI 腳本等 n8n 紀錄出現「published workflows」再開始測。
- **學到的事**：「服務啟動了」不等於「服務準備好了」。這類只在全新環境出現的問題，正是 CI 能抓到的。

### I1-3 測試腳本計分時當掉
- 檢查結果可能是 `None`（不是 True/False），加總時出錯，蓋掉了真正的失敗訊息。處理：記錄前一律轉成 True/False。

### I1-4 PowerShell 傳多行文字給 git 失敗
- 用 PowerShell 5 把多行提交說明直接傳給 `git commit`，被拆成好幾個參數。處理：說明先寫進檔案，再用 `git commit -F 檔案`。

## 第三期 I2 微調向量模型

### I2-1 模型訓練好了，系統卻還在用舊模型
- **現象**：重建後 `/api/policies/model` 回答「原始模型」。
- **原因**：app 映像在訓練完成前就建好了，`models/` 裡當時只有 README；之後啟動用的是舊映像。
- **處理**：訓練完再建置一次 app，確認容器裡有 `models/finetuned/model.onnx`。
- **學到的事**：模型檔和程式一樣要「部署」，改完要確認線上版本真的換了（所以加了 `/api/policies/model` 可以查）。

### I2-2 驗證題挑出的門檻太寬
- 用驗證題自動挑門檻，微調模型會選 0.21：找得到的題目變多，但無關問題（「今天股市收盤多少」）也比較容易被硬湊條文。
- **處理**：維持 0.35。寧可少找到一題，也不要對無關問題亂引用規定（找不到時 AI 還會換說法再查）。這是產品取捨，不是單看分數。

## 第三期 I3 多 Agent 協作

### I3-1 檢查員誤判：客人自己說的預算被當成亂編的金額
- **現象**：真實 AI 評測 18/20，「4 個人想去沖繩，每人預算 3 萬」被改成轉專人。
- **原因**：檢查員只承認工具回傳的數字；AI 把客人說的「3 萬」寫成「NT$ 30,000」，被當成編造的金額，退回兩次後改轉專人。
- **處理**：客人這句話裡的數字也算合法，並把「3 萬」「5 千」換算成數字。補一題模擬測試。
- **學到的事**：防護規則太嚴也會出錯（誤判），要用真實資料測，不能只用自己寫的假資料。

### I3-2 專員把不屬於自己的部分推給對方
- **現象**：同時問報價和取消規定，報價專員為「取消」建立轉接單、沒給價格；規定專員叫客人「請洽報價專員」。
- **原因**：每位專員都拿到客人的完整問題，看到別人負責的部分就想處理或推掉。
- **處理**：先在規則寫明「回答會合併、只寫自己的部分」；仍會發生，最後改成分流時就把問題拆開，每位專員只拿到自己那段（見 I3-4）。

### I3-3 AI 說「已為您轉給專人」，但沒有真的轉
- **現象**：工具紀錄沒有 request_human，回答卻說已轉專人，客人會以為有人會聯絡。
- **處理**：檢查員新增規則：回答提到轉接，但這位專員沒有成功呼叫 request_human，就退回重答。三次真實抽測中有兩次被這條規則擋下並改正。
- **學到的事**：AI 會「說它做了某件事」，要用工具紀錄核對，不能只看回答文字。

### I3-4 分流拆題時把「0 個人」改成「一個人」
- **現象**：改成拆題後評測 19/20，Q05「0 個人去京都」沒有拒絕，反而開始推薦行程。
- **原因**：分流 AI 改寫問題時自作主張修正成「一個人」，專員看不到原本不合理的輸入。
- **處理**：分流規則要求人數、金額、日期、姓名照抄；交給專員時附上客人原話，數字以原話為準。再測 20/20，抽測 3/3。
- **學到的事**：多 Agent 每多傳一手，資訊就可能失真；關鍵資料要保留原文。

## 第三期 I4 監控

### I4-1 測試寫錯網址（不是系統錯）
- 測試用 `/api/quotes/999999` 檢查「依路由樣板記錄」，但沒有這條路由，請求被正確歸到「其他」。改用存在的 `/api/quotes/{id}/events`，並多加一項「不存在的網址歸到其他」。

### I4-2 PowerShell 引號問題讓測試密碼出現在錯誤訊息
- **現象**：截圖指令把 `-e 變數=(讀取的值)` 拆錯，密碼被當成映像名稱，出現在錯誤訊息裡。
- **處理**：立刻換掉 sales 測試帳號密碼（`.env` 與資料庫一起更新，舊密碼失效）；新增 `tools/run_shots.ps1`：密碼先放進環境變數，docker 只傳變數名稱，命令列和錯誤訊息都不會出現密碼值。
- **學到的事**：密碼不要放在命令列參數上（會出現在錯誤訊息、指令紀錄、行程列表）。

### I4-3 截圖時頁面自動切換分頁
- 頁面載入時會依 AI 狀態自動切換分頁，跟腳本的點擊撞在一起，等不到元素。產生流量的部分改成直接呼叫 API。

### I4-4 全新環境的 Grafana 還沒載入儀表板
- 本機 CI（全新環境）監控測試 20/21：Grafana 健康檢查通過了，但儀表板查詢回 404；開發版不會發生。
- **原因**：Grafana 啟動後才開始載入自動建立的儀表板，要再等幾秒。和 I1-2 的 n8n 是同一類問題。
- **處理**：測試等儀表板出現（最多 60 秒）再檢查。

### I4-5 GitHub 上監控測試失敗（本機會過）
- **找原因**：GitHub 的詳細紀錄要登入才能看，改成讓 CI 把失敗項目和 Grafana 錯誤寫成「標註」，用公開 API 讀到。
- **原因 1**：`travel.json` 開頭有看不見的 BOM 標記（之前用 PowerShell 5 的 `Set-Content -Encoding utf8` 改檔，它會自動加 BOM），Grafana 解析 JSON 失敗：`invalid character 'ï'`。本機沒事是因為改檔前就已經載入過。
- **原因 2**：測試檢查「整份指標裡不能出現 999999」，但回應時間加總可能剛好是 0.0999999 這種數字。改成只檢查 route 標籤。
- **處理**：移除 BOM，並掃描全部檔案（只有需要 BOM 的 PowerShell 腳本保留）；測試改用正規表示式取出標籤。
- **學到的事**：本機會過、CI 不會過，通常是「環境不同」或「本機有舊狀態」；CI 從零開始，才抓得到這類問題。

## 第四期 J1 政府開放資料

### J1-1 網路上查到的舊下載網址已失效
- 記憶中的 `scenic_spot_C_f.json` 等網址回 404。到政府資料開放平臺（data.gov.tw）查到現行網址 `XMLReleaseAll_public/v2.0/Zh_tw/Attraction-json.zip`。

### J1-2 zip 裡第一個檔案不是資料
- 解析時直接讀 zip 的第一個檔案，結果是 `manifest.csv`，JSON 解析失敗。改成指定讀 `AttractionList.json`。

### J1-3 景點類型代碼憑印象寫錯
- 第一版代碼對照表寫到 18 類，實際資料有 1～27 和 254。下載官方《觀光資料標準 V2.0》PDF，用程式抽出文字找到第 14 節「景點類型代碼」，改成正確的 28 類。

### J1-4 測試不能動到真實資料

- **處理**：測試時把資料表換成暫存的複製表，結束後刪除，並檢查真實資料筆數不變。

## 第四期 J2 爬蟲

### J2-1 物件還沒設定好就被使用
- `Fetcher` 在讀 robots.txt 時就用到 `self.delay`，但它是讀完 robots.txt 才設定。先給預設值再讀。

### J2-2 User-Agent 寫中文造成錯誤
- `UnicodeEncodeError: 'latin-1' codec can't encode`：HTTP 標頭只能用英文字元。改成英文的 User-Agent。

### J2-3 測試自己觸發了限流
- 測試先連讀兩次 robots.txt，緊接著開始爬，1 秒內超過 3 次被回 429。爬蟲有正確等待並重試，是測試的時間安排問題；開始爬之前先等 1 秒。

### J2-4 網站還在跑舊程式
- 測試全部通過，但 n8n 觸發的爬取失敗，錯誤是已經修過的 J2-1。
- **原因**：用 `docker cp` 把新程式複製進容器，只影響之後「新開的」程式（測試）；網站本身是啟動時就載入程式碼的，一直跑著舊版。
- **處理**：重新建置並重啟 app，再由 n8n 觸發一次：成功。
- **學到的事**：改了程式要確認「正在服務的那個程式」也更新了；測試通過不等於線上版本是新的。

## 第四期 J3 旅遊網站改版

### J3-1 縣市照片卡片上的字看不清楚
- **現象**：首頁「探索台灣」的縣市名稱是深色字，壓在照片和暗色漸層上幾乎看不到。
- **原因**：CSS 寫了 `.site a { color: inherit }`（連結繼承深色字），它比 `.s-city { color: #fff }` 更「具體」（類別＋標籤 勝過 只有類別），所以白字被蓋掉。
- **處理**：改成 `.site a.s-city`，再加一點文字陰影。
- **學到的事**：CSS 不是「後寫的贏」，而是「越具體的贏」（specificity）；看截圖才發現得到，程式測試不會報錯。

### J3-2 行程卡片底部文字斷行很難看
- 「3 天｜剩 24 位」「起／人」被擠到兩行。改成可以整組換行、但每組文字不斷開（`white-space: nowrap`）。

### J3-3 飯店選項的圓點自己跑到上一行
- 舊樣式表對所有 `input` 設了 `display: block; width: 100%`，單選圓點也變成獨占一行。在前台用更具體的選擇器改回 `inline-block`。

### J3-4 舊樣式影響新網站
- 舊後台樣式直接寫在 `header`、`main` 標籤上，會套到新網站。把這些版面規則限定在 `.admin-app`（後台）底下。

### J3-5 AI 工具名稱顯示英文
- 真實 AI 測試時，聊天泡泡顯示「使用工具：search_local_info」：新增工具時忘了加中文名稱對照。補上「查景點／住宿」。
- **學到的事**：新增功能時，畫面上所有會出現的文字都要檢查一遍（使用者看到英文代號會困惑）。

### J3-6 CI 沒有開放資料
- CI 為了不依賴政府網站，不自動匯入開放資料；畫面測試改成先查有沒有資料，沒有就跳過景點相關檢查、改確認「資料準備中」提示正常顯示。

## 第四期 J4 收尾

### J4-1 全新安裝失敗：安裝包少了 supplier 資料夾
- **現象**：把新安裝包解壓到中文資料夾執行 Start.bat，前 4 個服務（含 React 前端）都建置成功，到第 5 個停住：「unable to evaluate symlinks in Dockerfile path … 旅遊AI客服系統\supplier: The system cannot find the file specified」。
- **原因**：J2 新增 `supplier/`（模擬供應商網站）時，只改了 docker-compose.yml 和 Start.bat，忘了加進打包清單 `build_installer.py`。開發版的資料夾什麼都有，所以測不出來。
- **處理**：打包清單加上 supplier；打包程式多一道檢查：docker-compose.yml 裡每個要建置的 Dockerfile 都必須在安裝包裡，少了就打包失敗。
- **學到的事**：「全新安裝測試」就是為了抓這種問題；而且要把「容易忘的事」變成程式自動檢查，而不是靠記得。

### J4-2 Docker 出現名稱是亂碼的資料區
- 使用者在 Docker Desktop 看到 `5ea9b654…` 的資料區。原因是 Alertmanager 映像本身宣告了資料區，但 docker-compose.yml 沒有幫它取名，Docker 就自動用亂碼命名。補上 `alertdata` 名稱。

### J4-3 文件寫錯服務數量
- 作品集、總複習、重建指南寫「13 個服務／容器」，全新安裝實際啟動的是 11 個（app、db、erp、website、mcp、mailpit、n8n、supplier、prometheus、alertmanager、grafana）。憑印象寫數字，沒有對照實際結果。已全部改正並重新輸出 PDF。
- **學到的事**：文件裡的數字要從實際執行結果抄，不要憑記憶。
