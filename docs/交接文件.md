# 交接文件：旅遊 AI 客服與報價系統

> 給接手維護的人。照這份文件做，可以把系統跑起來、改設定、查問題。全部資料為模擬資料。
> 撰寫：杜正威（系統由 Claude 協助開發）　最後更新：2026-11-03

## 1. 系統一覽
| 容器（服務） | 做什麼 | 對外埠 |
|---|---|---|
| app | FastAPI 後端＋網頁前端、AI 客服、RAG、採購 Agent、帳號、儀表板、評測、合作夥伴 API（/partner） | 8100 |
| db | PostgreSQL 15＋pgvector（報價、對話、向量、採購、通知、帳號、評測） | 不對外 |
| erp | 模擬 ERP 與供應商 API（SQLite） | 8101 |
| website | 模擬官網「晴空旅遊」，後端帶金鑰呼叫合作夥伴 API | 8103 |
| n8n | 自動化流程（啟動時自動匯入 4 個流程，含寄信） | 127.0.0.1:5678 |
| mailpit | 模擬信箱，n8n 寄的信都在這裡 | 127.0.0.1:8025 |
| mcp | MCP 伺服器（給外部 AI 工具） | 127.0.0.1:8102 |
| prometheus | 每 15 秒收集主系統指標、判斷 7 條告警規則 | 127.0.0.1:9090 |
| alertmanager | 告警寄信到 IT 信箱（Mailpit） | 127.0.0.1:9093 |
| grafana | 監控儀表板（帳號 admin，密碼見 .env 的 GRAFANA_PASSWORD） | 127.0.0.1:3000 |

後台帳號：`admin`（管理員：帳號、合作夥伴、執行評測）、`manager`（主管：可核准大額採購）、`sales`（業務）。初始密碼在 `.env` 的 ADMIN／MANAGER／SALES_PASSWORD（安裝版也寫在 `登入資訊.txt`），第一次啟動時建立；之後改密碼請用後台「系統管理」。

## 2. 啟動與停止
- 安裝版：`Start.bat`、`Stop.bat`（Docker 專案名稱 `travelai`）。
- 開發版：`docker compose -p travelquote up -d --build`、`docker compose -p travelquote down`。
- 兩個版本埠號相同，同時只能開一個。
- 改了程式後要重新建置：`docker compose -p <專案名> up -d --build`。

## 3. 設定（`.env`）
| 變數 | 用途 | 注意 |
|---|---|---|
| DB_PASSWORD | 資料庫密碼 | 建好資料庫後不要改，改了會連不上（見常見問題） |
| ADMIN／MANAGER／SALES_PASSWORD | 三個預設帳號的初始密碼 | 只在帳號不存在時使用；之後改 .env 不會改到既有帳號 |
| STAFF_TOKEN／MANAGER_TOKEN | 系統整合用的服務權杖（測試程式用） | 同仁請用帳號登入 |
| PARTNER_DEMO_KEY | 模擬官網用的合作夥伴金鑰 | 其他合作夥伴由管理員在後台建立 |
| SALES／MANAGER／IT_EMAIL | n8n 通知信的收件人 | 預設 @travel.example（模擬） |
| ANTHROPIC_API_KEY | Claude API 金鑰 | 不可外流，有效期限到期要換 |
| CHAT_MODEL | AI 客服模型 | 預設 claude-haiku-5-5 |
| PROCUREMENT_MODEL | 採購比價模型 | 預設 claude-opus-5-5 |
| DAILY_CHAT_LIMIT／DAILY_COST_LIMIT_USD | 每日 AI 次數／費用上限 | 預設 200 次／1 美元，超過暫停到隔天 |
| MANAGER_APPROVAL_THRESHOLD | 採購金額達到多少要主管核准 | 預設 30000 |
| ERP_API_KEY | 主系統呼叫 ERP 的金鑰 | |
| AUTOMATION_TOKEN | n8n 呼叫主系統的權杖 | 只能呼叫通知、報表、重送 |
| METRICS_TOKEN | Prometheus 讀取 /metrics 的權杖 | 沒設定時 /metrics 不開放 |
| GRAFANA_PASSWORD | Grafana 管理員密碼 | 只在第一次啟動時套用 |
| RAG_MODEL | finetuned（預設，有微調模型就用）或 base（固定用原始模型） | 換模型會自動重建向量 |
| APP_PORT／ERP_PORT／MCP_PORT／N8N_PORT／PROMETHEUS_PORT／ALERTMANAGER_PORT／GRAFANA_PORT | 埠號 | |

改完 `.env` 要重新啟動：`docker compose -p <專案名> up -d`。

## 4. 常見維護工作
| 工作 | 怎麼做 |
|---|---|
| 換 Claude 金鑰 | Console 建新金鑰 → 貼進 `.env` → 重新啟動 → 刪掉舊金鑰 |
| 修改旅遊規定 | 改 `data/policies/*.md`（格式：`## 第N條 標題`）→ 重新建置 app。啟動時偵測到內容變了會自動重建向量 |
| 新增行程或飯店 | 在資料庫新增 `packages`／`hotels`；新飯店的供應商報價要在 `supplier_offers` 補上 |
| 修改 n8n 流程 | 改 `automation/build_workflows.py` → 執行產生 JSON → `docker restart <專案名>-n8n-1`（啟動時自動匯入） |
| 查看紀錄 | `docker logs <專案名>-app-1 --tail 100` |
| 備份資料庫 | `docker exec <專案名>-db-1 pg_dump -U travel travel > backup.sql` |
| 清空測試資料重來 | `docker compose -p <專案名> down -v` 後重新啟動（會刪除全部資料） |
| 新增同仁帳號／停用離職同仁 | 管理員登入 → 系統管理 → 新增帳號／停用（停用立即登出） |
| 忘記密碼、帳號被鎖 | 管理員在系統管理按「重設密碼」，會一併解鎖 |
| 新增合作夥伴（官網、平台） | 管理員在系統管理建立，金鑰只顯示一次，請立即交給對方；外洩就停用再建新的 |
| 改 AI 規則或換模型 | 改完後到「AI 評測」執行一次，分數下降就看沒通過的題目；新發現的問題要補進 `evals.py` 題組 |
| 改收件人 | 改 `.env` 的 SALES／MANAGER／IT_EMAIL 後重新啟動 n8n |
| 規定改版後重新訓練向量模型 | 在 `tools/finetune/dataset.py` 補問法 → `docker build -t travelquote-finetune tools/finetune` → `docker run --rm -v <專案>:/p travelquote-finetune python /p/tools/finetune/train.py` → 重新建置 app → 在 app 容器跑 `python rag_compare.py` 比較 |
| 看系統健康 | Grafana http://localhost:3000；告警規則 http://localhost:9090/alerts；告警信在 Mailpit |
| 改告警規則 | 改 `monitoring/prometheus/alerts.yml` → `docker restart <專案名>-prometheus-1` |
| 改前端畫面 | 改 `frontend/src/` → 重新建置 app（Docker 會先跑前端測試再建置）。要即時預覽可在有 Node 的電腦 `cd frontend && npm install && npm run dev`（API 會轉到 8100） |
| 切換多 Agent／單一 Agent | 畫面上 AI 客服可切換；用「AI 評測」的兩個按鈕各跑一次比較 |

## 5. 常見問題
| 現象 | 原因 | 處理 |
|---|---|---|
| 網頁一直轉圈或 500 | 資料庫密碼和既有資料不符（換過 `.env`） | 改回原密碼；或確定不要資料時 `down -v` 重建 |
| AI 客服顯示「尚未啟用」 | 沒有金鑰 | 在 `.env` 加金鑰後重新啟動 |
| AI 客服顯示「金鑰無效」 | 金鑰過期或被刪 | 換新金鑰 |
| AI 客服顯示「已達上限」 | 今日次數或費用超過上限 | 隔天恢復；確定要用可調高上限 |
| 報價成交但 ERP 顯示失敗 | ERP 故障或連不上 | 後台「ERP 同步」看錯誤訊息；恢復後按「重送全部失敗」，n8n 每 10 分鐘也會自動重送 |
| 採購單「下單失敗」 | 供應商 API 故障 | 恢復後在採購頁按「重送」 |
| 業務按核准出現「需要主管核准」 | 金額達門檻或超出預算 | 用主管帳號登入再核准 |
| 登入顯示「帳號已鎖定」 | 密碼連錯 5 次 | 等 15 分鐘，或請管理員重設密碼 |
| 合作夥伴說一直收到 429 | 超過每分鐘上限 | 在系統管理看呼叫紀錄；請對方依 Retry-After 等待，或調高上限 |
| 合作夥伴 API 文件頁空白 | 文件頁的元件要從網路載入 | 確認可上網；或直接給對方 `/partner/openapi.json` |
| 沒收到通知信 | 同一件事已通知過（不重複寄），或 n8n 沒在跑 | 看 Mailpit（8025）與後台通知中心；`docker logs <專案名>-n8n-1` |
| AI 回答規定說「文件沒有提到」 | 規定沒寫到，或問法差太多 | 到「旅遊規定」分頁直接搜尋看相似度；需要的話補強條文寫法 |
| 啟動失敗 port is already allocated | 埠號被其他程式或另一個版本占用 | 先停掉另一個版本，或改 `.env` 的埠號 |

## 7. 測試
在容器內執行（先 `docker cp tools/*.py <專案名>-app-1:/code/`）：
`api_test.py`、`auth_test.py`、`partner_test.py`、`agent_test.py`、`multi_agent_test.py`、`procurement_test.py`、`automation_test.py`、`eval_test.py`、`rag_eval.py`、`monitor_test.py`（要帶 `-e GRAFANA_PASSWORD=...`）；Email 用 `email_test.py prepare`→執行 n8n 流程→`check`→再執行→`dedupe`；MCP 在 mcp 容器執行 `mcp_test.py`；真實 AI 評測 `ai_eval.py [說明] [single|multi]`；RAG 模型比較 `rag_compare.py`。
前端元件測試在建置 app 時自動執行（`frontend/src/app.test.jsx`）。
**一次跑全部（和 GitHub CI 相同）**：Git Bash 執行 `PROJECT=citest APP_PORT=8200 bash tools/ci_run.sh`（另開一組埠，不影響開發版）。
截圖腳本用 `powershell -File tools\run_shots.ps1 -Script <腳本> [-Out <資料夾>]`，密碼由環境變數傳入，不會出現在命令列。
模擬測試（假 AI）不花 API 額度，結束會自動清掉測試產生的用量紀錄；`live_*.py` 會呼叫真的 Claude、會花額度。
**注意**：測試會建立測試用的報價、採購單、通知。展示前要重建展示資料：`python seed_demo.py`（會清空報價、對話、採購、通知等資料，並用真實 AI 重建，約花 0.1–0.2 美元）。

## 8. 已知限制與待辦
- ~~報價沒有出發日期~~（第二期 H1 已補上）；~~團費定義不清~~（規定第 1 條已寫明含住宿）。
- 模擬供應商的確認編號存在記憶體，ERP 容器重啟會重新編號；Mailpit 的信重啟後清空。
- 通知信寄到模擬信箱；要寄真實 Email 需改成 n8n 的 SMTP 節點並設定公司信箱帳號。
- 合作夥伴呼叫上限以資料庫計數，大流量要改用 Redis。
- AI 評測是規則式評分，不判斷語氣與說明品質，仍需人工抽查。
