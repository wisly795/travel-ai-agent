# 從零重建指南

> 給第一次接觸這個專案的人：照這份文件，從一台什麼都沒裝的 Windows 電腦，到系統跑起來、測試全部通過、模型重新訓練、CI 設定好。
> 所有資料皆為模擬資料（台灣景點與旅宿為交通部觀光署開放資料）。

## 0. 你需要準備
| 項目 | 必要嗎 | 說明 |
|---|---|---|
| Windows 10／11（記憶體 16 GB 以上建議） | 必要 | 11 個容器同時執行約用 6～8 GB |
| Docker Desktop | 必要 | 安裝後開啟，等左下角顯示 Engine running |
| 網路 | 第一次必要 | 下載映像、套件、向量模型、開放資料（約 3 GB） |
| Git | 要改程式才需要 | 從 GitHub 下載原始碼 |
| Claude API 金鑰 | 要用 AI 功能才需要 | console.anthropic.com 申請；沒有金鑰時 AI 客服顯示「尚未啟用」，其他功能照常 |
| Node.js、Python | 不需要 | 前端建置、測試都在 Docker 裡進行 |

## 1. 取得程式
二選一：
- 安裝包：解壓 `旅遊AI客服系統_安裝包_YYYYMMDD.zip`（含微調模型）。
- 原始碼：`git clone https://github.com/wisly795/travel-ai-agent.git`（不含微調模型與 .env，見第 4 步）。

## 2. 第一次啟動
1. 執行 `Start.bat`。
2. 它會自動：
   - 產生 `.env`（隨機密碼與權杖）和 `登入資訊.txt`（帳號密碼）
   - 建置映像。資料夾路徑有中文時，一般建置會失敗，它會自動改用相容模式
   - 啟動 11 個容器
   - 第一次啟動時，在背景匯入政府開放資料（約 1 分鐘）
3. 完成後瀏覽器打開 http://localhost:8100（旅遊網站）；業務後台在 http://localhost:8100/admin，帳號密碼看 `登入資訊.txt`。
4. 第一次約 10～15 分鐘；之後啟動約 1 分鐘。停止用 `Stop.bat`（資料保留）。

## 3. 打開 AI 功能（需要金鑰）
1. 用記事本打開 `.env`，在 `ANTHROPIC_API_KEY=` 後面貼上金鑰，存檔。
2. 再執行一次 `Start.bat`。
3. 金鑰只放在 `.env`，不要貼到程式、聊天、Git 或截圖。每日上限預設 200 次、1 美元（`.env` 的 DAILY_CHAT_LIMIT、DAILY_COST_LIMIT_USD）。

## 4. 從原始碼建置時才需要：微調向量模型
GitHub 上沒有放模型檔（113 MB）。沒有模型時系統自動改用原始模型，功能照常，只是 RAG 找條文的準確度低一點。要重新產生：
```
docker build -t travelquote-finetune tools/finetune
docker run --rm -v <專案資料夾>:/p travelquote-finetune python /p/tools/finetune/train.py
```
- 第一次要下載原始模型（約 500 MB），訓練本身約 1 分鐘（CPU 即可）。
- 產出 `models/finetuned/`，重新建置 app（`docker compose -p travelquote up -d --build app`）後生效。
- 驗證：在 app 容器執行 `python rag_compare.py`，比較原始與微調模型。

## 5. 確認一切正常：跑測試
### 一次跑全部（和 GitHub CI 相同，不花 API 額度）
Git Bash 執行：
```
PROJECT=citest APP_PORT=8200 bash tools/ci_run.sh
```
會另外開一組埠號（8200 起）、隨機密碼，建置全部容器、跑全部測試，最後清除。和正在使用的系統互不影響。

### 個別測試
在 app 容器內執行（先 `docker cp tools/. <專案名>-app-1:/code/`）：

| 測試 | 驗證什麼 |
|---|---|
| `api_test.py` | 全部 API |
| `auth_test.py`、`partner_test.py` | 帳號、合作夥伴 API |
| `agent_test.py`、`multi_agent_test.py`、`procurement_test.py`、`eval_test.py` | AI 流程（假 AI，不花錢） |
| `automation_test.py`、`email_test.py` | n8n 自動化與寄信 |
| `rag_eval.py`、`rag_compare.py` | RAG 檢索 |
| `monitor_test.py` | 監控（要帶 `-e GRAFANA_PASSWORD=...`） |
| `opendata_test.py`、`crawler_test.py` | 開放資料匯入、爬蟲 |
| `ai_eval.py` | 真實 AI 20 題評測（會花少量額度） |

畫面測試（瀏覽器）：`powershell -File tools\run_shots.ps1 -Script ui_site_test.py -Out 資料夾名稱`。

## 6. 展示前準備示範資料
測試會留下測試資料。展示前在 app 容器執行 `python seed_demo.py`：清空測試資料，再用真實流程（含真實 AI，約 0.1 美元）重建報價、對話、採購與官網串接。

## 7. 設定自己的 GitHub CI
1. 在 GitHub 建立空的儲存庫，把程式推上去。
2. `.github/workflows/ci.yml` 已經寫好：每次上傳到 main，自動建置並跑全部測試。
3. 不需要設定任何密碼或金鑰：CI 用隨機密碼與假 AI。
4. 失敗時，失敗的測試項目會寫成「標註」（Annotations），不用登入也看得到原因。

## 8. 系統是怎麼一步一步做出來的（想從頭重做一遍的人看）
每一階段都有測試報告（`docs/*_測試報告.md`）、錯誤紀錄（`docs/錯誤紀錄.md`）、截圖（`docs/過程截圖/`），Git 紀錄也保留了每個階段的提交。建議依序重做：

| 順序 | 階段 | 先做什麼 | 完成的標準 |
|---|---|---|---|
| 1 | 查行程與報價 | FastAPI＋PostgreSQL，報價公式放後端 | `api_test.py` |
| 2 | A AI 客服 | Claude Tool Use、自己寫 Agent 迴圈、價格只能用工具 | `agent_test.py` 假 AI 測試 |
| 3 | B RAG | 規定切段、pgvector、相似度門檻、回答附條號 | `rag_eval.py` |
| 4 | C 後台＋ERP | 狀態流程、ERP 冪等、失敗重送 | 故障演練 |
| 5 | D 採購 Agent | 較強模型比價、只建草稿、人核准 | `procurement_test.py` |
| 6 | E n8n、F MCP | 自動化流程、MCP 伺服器 | `automation_test.py`、`mcp_test.py` |
| 7 | G 交付 | 安裝包、Start.bat、交接文件 | 中文路徑全新安裝 |
| 8 | H1～H6 | 出發日期、帳號、儀表板、官網 API、Email、AI 評測 | 各自測試＋真實評測 20/20 |
| 9 | I1～I5 | CI、微調、LangGraph 多 Agent、監控、React | CI 綠燈 |
| 10 | J1～J3 | 開放資料、爬蟲、旅遊網站 | `opendata_test.py`、`crawler_test.py`、`ui_site_test.py` |

## 9. 常見卡關
| 卡在哪 | 解法 |
|---|---|
| Start.bat 說「請先開啟 Docker Desktop」 | 開 Docker Desktop，等 Engine running |
| port is already allocated | 8100 等埠號被占用；先停掉其他版本，或改 `.env` 的埠號 |
| 建置失敗 | 確認網路；資料夾路徑有中文會自動改相容模式，若仍失敗把資料夾搬到英文路徑 |
| 探索台灣顯示「資料準備中」 | 開放資料還在匯入（約 1 分鐘），或沒有網路；後台「資料與爬蟲」看匯入紀錄 |
| AI 客服顯示「尚未啟用」 | `.env` 沒有金鑰 |
| 其他問題 | 看 `docs/交接文件.md` 第 5 節與 `docs/錯誤紀錄.md` |
