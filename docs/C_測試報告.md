# C 階段 業務後台與 ERP 串接：測試報告

- 日期：2026-11-03
- 截圖：`docs/過程截圖/C_後台與ERP/`
- 新服務：模擬 ERP（`erp/app.py`，獨立容器，port 8101，SQLite 儲存，API 金鑰驗證）

## 新功能
| 功能 | 說明 |
|---|---|
| 報價狀態 | 已報價 → 成交／取消；成交後仍可取消；取消後不能再成交；每次變更寫入 `quote_events` |
| ERP 同步 | 改成成交時自動呼叫 ERP `POST /api/orders`，結果寫入 `erp_syncs`（成功／失敗、次數、ERP 單號、錯誤訊息） |
| 冪等 | 以 `Q-報價編號` 當外部編號，重送不會在 ERP 產生第二筆訂單 |
| 重送 | 單筆重送、重送全部失敗（給 E 階段自動化定時呼叫） |
| 模擬故障 | 後台可讓 ERP 進入維修模式（回 503），展示失敗與重送 |
| AI 對話紀錄 | 每次提問、回答、工具輸入與結果、模型、花費 |
| 轉接單 | 待處理／已處理 |
| 用量 | 今日 AI 次數與花費 vs 上限 |

C 階段重點檢查（API）：
- 成交並同步 ERP、已成交不能再成交、重送不重複建單（ERP 單號相同、次數 2）
- 不允許的狀態 422、未登入 401、不存在的報價 404
- ERP 故障時記錄 503 失敗、故障中重送仍失敗、恢復後重送成功、次數累計正確
- 成交後可取消、取消後不能成交、狀態變更有紀錄
- 新的後台 API 未登入一律 401

## 觀察
- 瀏覽器實測時，客人說「我叫後台測試」，AI 不認為這是姓名，一再請客人提供全名，所以這次沒有建立報價單（截圖 03 的 #18、#19）。規則本來就要求知道姓名才建立，屬於合理的保守行為；前面「測試小明」「測試一號」都能建立。正式使用時客人會給真實姓名，不需修改。
- AI 遇到「改期」這種規定沒寫到的問題，會說文件沒有提到，並提供替代方案與轉專人（截圖 03 的 #20）。
