# J2 模擬供應商網站＋爬蟲：測試報告

- 日期：2026-11-04
- 截圖與輸出：`docs/過程截圖/J2_爬蟲/`、`docs/過程截圖/J2_crawler_test輸出.txt`

## 1. 為什麼爬「模擬網站」
真實訂房網站（Booking、Agoda 等）的服務條款禁止爬取，也會擋機器人；放在公開作品集有法律風險。所以另外架一個「雲遊旅宿比價網」（全部虛構），把真實網站會遇到的狀況都做進去，爬蟲技術一樣完整。

## 2. 模擬供應商網站（supplier 容器，本機 http://localhost:8104）
| 特性 | 內容 |
|---|---|
| 規模 | 5 個城市、30 家住宿、每家 3 種房型 |
| 列表分頁 | 每頁 8 家，「下一頁」連結（共 4 頁） |
| 詳細頁 | 房型與每晚價格表格、價格日期、限時特價標記；售完沒有價格 |
| robots.txt | 禁止 /admin、/checkout；Crawl-delay 1 秒 |
| 限流 | 同一來源 1 秒內超過 3 次回 429，附 Retry-After |
| 價格變動 | 依「飯店＋日期」決定，同一天固定、隔天變；偶爾漲跌 15% 以上 |
| 測試用 | `/admin/advance-day`（模擬隔天）、`/admin/truth`（當天真正價格，用來核對）——robots.txt 禁止爬蟲進入 |

## 3. 爬蟲（`backend/app/crawler.py`）
| 功能 | 做法 |
|---|---|
| 遵守 robots.txt | 先讀規則，禁止的路徑不抓；依 Crawl-delay 控制每次請求的間隔 |
| 表明身分 | User-Agent：`TravelQuoteBot/1.0` |
| 翻頁 | 跟著「下一頁」連結，最多 30 頁，避免無限迴圈 |
| 解析 HTML | BeautifulSoup，用 class／data 屬性找欄位；找不到就丟出「網站可能改版」錯誤，一家失敗不影響其他家 |
| 重試 | 429、5xx 依 Retry-After 等待，最多 3 次 |
| 保存 | 住宿資料＋價格歷史；價格**有變才寫**一筆 |
| 價格變動通知 | 漲跌超過 15%、售完、恢復販售 → 寫進通知中心（同一天同一間房只通知一次） |
| 紀錄 | 每次爬取：頁數、住宿數、變動數、通知數、請求數、重試數、秒數、錯誤 |
| 排程 | n8n 流程 6 每天 05:00；管理員也可手動觸發 |
| API | `/api/supplier-prices`（最新價格，比價參考）、`/api/admin/crawler/runs`、`/api/admin/crawler/changes` |

## 4. 測試結果：`crawler_test.py` 19/19
| 項目 | 結果 |
|---|---|
| 讀到 Crawl-delay、不抓 robots.txt 禁止的路徑 | 通過 |
| 爬完 30 家、4 頁；請求有間隔、沒被限流 | 通過 |
| **抓到的價格和網站真實價格逐筆完全一致（含售完 12 間房）** | 通過 |
| 第一次沒有變動；同一天重爬不重複寫入 | 通過 |
| 模擬隔天：偵測到 75 筆變動；大幅漲跌發通知（例如「沖繩 海風飯店 標準雙人房 漲 18%：NT$ 4,590 → NT$ 5,400」）；同一天不重複通知 | 通過 |
| 限流改成每秒 1 次、不等待連抓：遇到 429 等待後重試成功 | 通過 |
| 網站改版找不到欄位：回報清楚的錯誤；沒有資料時不會無限翻頁 | 通過 |
| API 依城市查詢、沒登入不能觸發爬蟲 | 通過 |

**n8n 實際觸發**：35 次請求、34 秒（每秒最多 1 次）、0 次重試、30 家全部成功。

## 5. 遇到的問題
見錯誤紀錄 J2-1～J2-4：物件還沒設定好就被使用、User-Agent 不能寫中文、測試自己觸發限流、**網站還在跑舊程式（docker cp 只影響新開的程式）**。

## 6. 未測項目
