## 1. 做了什麼
```text
主系統 /metrics ──每 15 秒──→ Prometheus ──判斷告警規則──→ Alertmanager ──寄信──→ 模擬信箱（IT）
                                   └──────────────→ Grafana 儀表板
```
| 元件 | 內容 |
|---|---|
| 主系統指標 `backend/app/metrics.py` | 請求數（依方法、路由樣板、狀態碼）、回應時間分布；營運指標：今日 AI 次數與花費、上限、ERP 同步失敗、待核准採購、待處理轉接、最新評測通過率、資料庫是否正常 |
| `/metrics` 保護 | 要帶 `METRICS_TOKEN`，沒帶或錯誤回 404（不讓外人知道有這個頁面） |
| Prometheus | 每 15 秒抓一次，資料保留 15 天；權杖由啟動腳本寫成檔案，設定檔不放權杖 |
| 告警規則（7 條） | 主系統停止回應、資料庫無法查詢、錯誤率 > 5%、回應變慢（P95 > 2 秒）、AI 花費超過上限 80%、ERP 同步失敗超過 30 分鐘、AI 評測通過率 < 90% |
| Alertmanager | 告警寄到 it@travel.example（Mailpit 模擬信箱，不會真的寄出），恢復時也通知 |
| Grafana | 自動建立資料來源與「旅遊系統監控」儀表板，需登入（admin，密碼在 `.env` 的 GRAFANA_PASSWORD） |
| 埠號 | 9090、9093、3000 都只開在本機（127.0.0.1） |

設計重點：路由用「樣板」（`/api/quotes/{quote_id}`）而不是實際網址，不存在的網址都歸到「其他」，避免指標數量被亂打的網址撐爆。
